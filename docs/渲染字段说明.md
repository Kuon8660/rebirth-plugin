# rebirth-plugin 渲染数据与字段说明

> 本文档说明异世界转生功能从触发指令到渲染出图全过程中用到的**数据字段**，
> 帮助理解每个字段代表什么、来自哪里、类型与示例值。
>
> 更新日期：2026-09-07 · 适用插件版本：0.6.0

---

## 一、功能链路速览

```
用户发指令
   │
   ├─ 「异世界转生」──────────→ RebirthPlugin.rebirth()
   ├─ 「#ai异世界转生」(即梦) → AiDrawPlugin.aiRebirth()
   │
   ▼
① 生成/复用转生信息（读/写 rebirth.db · rebirth_info 表）
   │
② 【AI 流程专属】调即梦绘图 → 图片存本地 resources/rebirth/ai/ → 路径写回 rebirth_info.aiImage
   │
③ RPG 每日签到 + 升级 + 发属性点（读/写 rpg.db · rpg_user 表）
   │
④ 组装 renderData（把昵称/头像/四维加成等合并）
   │
⑤ reRender(renderData) → 用 resources/rebirth/index.html 模板渲染出 PNG → 发送
```

- 普通转生数据库：`data/rebirth.db`
- 类RPG等级数据库：`data/rpg.db`（**独立库，独立表**）
- 渲染模板：`resources/rebirth/index.html`
- 渲染产物：`tmp/rebirth/{日期}-{user_id}.png`
- AI 角色图（即梦产物）：`resources/rebirth/ai/{user_id}_{yyyyMMdd}.png`

## 二、传给渲染模板的字段（renderData）

这两处命令最终都会构造一个 `renderData` 对象，作为 art-template 模板的变量传入 `index.html`。

### 2.1 模板实际使用（index.html 中 `{{ 字段 }}` 引用）

| 字段 | 类型 | 含义 | 来源 |
|------|------|------|------|
| `title` | string | 卡片大标题，固定为 `异世界转生` | 代码常量 |
| `avatarUrl` | string | 用户 QQ 头像 URL | `Bot.pickFriend(uid).getAvatarUrl()` |
| `userName` | string | 用户昵称（群聊优先取群名片，私聊取好友昵称） | `Bot.pickFriend/getInfo` + 群成员信息 |
| `race` | string | 种族（中文，如 `龙族`） | 转生生成 |
| `job` | string | 职业（中文，如 `龙骑士`） | 转生生成 |
| `gender` | string | 性别（`男` / `女`） | 转生生成 |
| `bodyType` | string | 体型（`瘦弱/健壮/苗条/魁梧`） | 转生生成 |
| `hairColor` | string | 发色（如 `蓝绿渐变`） | 转生生成 |
| `eyeColor` | string | 瞳色（如 `紫色`） | 转生生成 |
| `strength` | number | 力量（基础值 + RPG 加成后展示） | 转生随机 + RPG bonus |
| `agility` | number | 敏捷 | 同上 |
| `intelligence` | number | 智力 | 同上 |
| `charisma` | number | 魅力 | 同上 |
| `luckValue` | number | 幸运值（1–100） | 转生随机 |
| `specialSkill` | string | 特殊技能（中文名） | 转生随机 |

### 2.2 传入但模板当前未展示

| 字段 | 类型 | 含义 |
|------|------|------|
| `user_id` | number | 目标用户的 QQ 号（renderData 里也有，用于命名输出文件） |
| `content` | string | 预留占位内容，恒为 `测试内容` |
| `aiImageDataUri` | string | **AI 角色图**转成 base64 的 data URI（空串表示没有）。已复原的模板未使用此字段 |

> ⚠️ **关于「AI 图片路径」**
> - 数据库里存的字段是 `rebirth_info.aiImage`，值为**本地文件相对路径**（如 `plugins/rebirth-plugin/resources/rebirth/ai/123_20260907.png`）。
> - `renderData.aiImageDataUri` 则是把该图片读出来转成 base64 的**内联图**（用于曾尝试的“AI 图作卡片背景”）。
> - 当前 `index.html` 已复原，不再把 AI 图当背景；若想展示等级/AI 立绘，需在模板加对应 `{{ 字段 }}` 并传入（见第六节）。

### 2.3 普通卡 vs AI 卡差异

| 项目 | 「异世界转生」 | 「#ai异世界转生」 |
|------|--------------|-----------------|
| 是否生 AI 图 | 否 | 是（即梦） |
| `userName`/`avatarUrl` | 有 | 有 |
| `aiImageDataUri` | 固定 `''` | AI 图 base64（或无 AI 图时 `''`） |
| 是否含转生 | 是 | 是 |

## 三、转生数据库字段（rebirth.db → rebirth_info 表）

| 字段 | 类型 | 含义 |
|------|------|------|
| `user_id` | INTEGER (PK) | 用户 QQ 号 |
| `race` | TEXT | 种族 |
| `job` | TEXT | 职业 |
| `gender` | TEXT | 性别 |
| `bodyType` | TEXT | 体型 |
| `hairColor` | TEXT | 发色 |
| `eyeColor` | TEXT | 瞳色 |
| `strength` | INTEGER | 力量（转生随机基础值，**不含 RPG 加成**） |
| `agility` | INTEGER | 敏捷 |
| `intelligence` | INTEGER | 智力 |
| `charisma` | INTEGER | 魅力 |
| `luckValue` | INTEGER | 幸运值 1–100 |
| `specialSkill` | TEXT | 特殊技能 |
| `aiImage` | TEXT | **AI 立绘本地相对路径**（可为 NULL/空，表示尚无 AI 图） |
| `createdTime` | DATETIME | 记录创建时间（本地时区） |

> 特性：该表**每个自然日清空一次**（凌晨 `DELETE`），故转生信息每日重置、每用户每日最多一条。

## 四、类RPG 等级数据库字段（rpg.db → rpg_user 表，独立模块）

| 字段 | 类型 | 含义 |
|------|------|------|
| `user_id` | INTEGER (PK) | 用户 QQ 号 |
| `level` | INTEGER | 异世界等级（0 → 100） |
| `exp` | INTEGER | 当前累计经验（未升级部分） |
| `points` | INTEGER | 可用属性点（每 5 级 +1，可分配） |
| `bonus_strength` | INTEGER | 分配到力量的永久加成 |
| `bonus_agility` | INTEGER | 分配到敏捷的永久加成 |
| `bonus_intelligence` | INTEGER | 分配到智力的永久加成 |
| `bonus_charisma` | INTEGER | 分配到魅力的永久加成 |
| `last_checkin` | TEXT | 最近一次签到日期（`yyyy-mm-dd`，用于每日去重） |
| `created_time` | DATETIME | 建档时间 |

相关配置：`config/rpg.json`（经验曲线 `expCoeff`/`expPower`、签到经验 `expPerCheckin`、首级下限 `minExpToNext`、满级 `maxLevel`、属性点间隔 `attrPointEveryLevels`）。

## 五、config 相关文件

| 文件 | 用途 |
|------|------|
| `config/config.json` | 总开关：`useimage`（转生是否用图片渲染） |
| `config/rebirth.json` | 转生随机池：种族/职业/技能/发色… 及各维度属性修正 |
| `config/rpg.json` | RPG 等级系统参数 |
| `config/ai.json` | 即梦(AI) 绘图配置：`enable`、`jimeng.base_url/sessionid/model/ratio/resolution` 等 |

## 六、想在卡片上显示「等级 / AI立绘」如何接入（进阶）

当前复原的模板不含等级与 AI 立绘，若想加上，只需两步：

**1) 渲染前把等级/立绘字段塞进 renderData**（例如在 `rebirth.js` 组装 renderData 处）：
```js
import { getPlayer } from './rebirthRpg.js'
const p = await getPlayer(targetUserId)
renderData.level = p.level          // 异世界等级
renderData.levelExp = `${p.exp} / 所需经验`
renderData.aiImagePath = info.aiImage || ''   // AI 图本地相对路径
```

**2) 在 `index.html` 模板对应位置加插值**：
```html
<p>等级: Lv.{{ level }}</p>
```
> 若要把 AI 图作为整卡背景，模板里需恢复 `background-image: url('{{ aiImageDataUri }}')` 之类的写法（data URI 已由 `aiImageDataUri` 提供）。

## 七、常见疑问

- **四维数值为什么可能比转生随机的大？** 因为展示时叠加了 RPG `bonus_*` 永久加成；数据库里 `rebirth_info` 存的是随机基值。
- **AI 图存在哪？** `resources/rebirth/ai/`，命名 `{user_id}_{yyyyMMdd}.png`，路径记录在 `rebirth_info.aiImage`。
- **同一天重复触发会重复生成/签到吗？** 不会。转生复用 DB 记录；签到靠 `rpg_user.last_checkin` 去重；AI 图靠 `aiImage` 路径存在与否复用。
